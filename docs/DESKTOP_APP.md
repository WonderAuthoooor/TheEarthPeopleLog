# 地球人日志工作室：桌面应用设计
版本：v0.2｜日期：2026-10-18｜时区：Asia/Shanghai（+08:00）。
性质：第1—9节保留设计依据与目标，不等于所有功能均已实现。用户随后授权实施一屏工作台，0.2内部测试版的真实能力、操作和验证统一见第10节。旧MVP的使用说明以AUTOMATION.md为准。

## 1. 产品目标与边界
把现有素材到草稿流程做成可独立安装的Windows桌面应用。用户从桌面图标进入项目，完成视频获取、评论归档、文稿和配音、预览与导出；日常使用不需要打开CMD、配置Python或寻找job.json。
核心目标是减少一条内容的实际制作时间和返工，保持证据、原始素材与费用可追溯。评估单位是每条内容的人工工时、技术失败率、返工次数和真实成本，不以功能数量替代账号验证。
“地球人日志工作室”是建议产品名；PySide6、布局、迭代顺序均为设计建议，不伪称用户已选定。
新闻核查、评论真实、素材使用依据和文明评分沿用EDITORIAL/CONTENT/CIVILIZATION，不在本文件重新定义。项目仍先做草稿；发布按已有授权与真实平台条件执行。

## 2. 现有版本审查
当前CMD只负责寻找Python、进入仓库并启动Tk桌面界面，不是用户被迫用命令行编辑。以下是代码审查结论，不是未经执行的故障实测：

| 已有实现 | 对正式应用的不足 | 改进 |
|---|---|---|
| run-pipeline.ps1优先使用Codex缓存里的Python | 迁移电脑、删除缓存后无法保证启动 | 打包运行时、字体策略、FFmpeg及依赖，提供安装程序和桌面入口 |
| core.ROOT/STORE指向代码所在目录 | 安装目录若不可写，任务保存可能失败；代码和用户数据耦合 | 安装目录只读，工作区由用户选择，配置放用户应用数据目录 |
| 四页Tk表单与外部播放器 | 选段依靠输入秒数，修改文字看不到画面变化 | 工作台内嵌预览、可视选段、文本与评论位置预览 |
| daemon工作线程，处理时整体禁用界面 | 导出时不能准备另一条内容；无取消和可恢复队列 | 独立worker进程、持久任务队列、仅锁定运行版本 |
| FFmpeg subprocess.run最长600秒超时 | 只有阶段文字，没有实时编码进度 | 读取FFmpeg progress，提供取消及阶段状态，超时按实际任务策略设置 |
| 文件排他锁与修订号保护 | 异常关闭会遗留运行锁，需确认进程状态 | 应用管理自己的运行租约、心跳和恢复流程；不得自动清除仓库协作锁 |
| 原子保存与输出哈希缓存 | 尚无编辑中的自动保存、项目历史列表或升级迁移 | 文档自动保存、版本快照、导入校验和向前兼容迁移 |
| 单帖下载和手动截图导入 | 热点发现、评论抓取还没有实现 | 先改进已有效流程；候选发现另接服务与限额 |
| 可选MiniMax适配器，错误不自动重试 | 没有跨日预算和请求结果未知状态；写稿端点已标deprecated | 供应商适配隔离、用量账本、预算校验、请求回执与人工核对 |
| 审核文件和15项离线检查 | 未做干净Windows安装、断电、磁盘满、升级恢复及全面UI验收 | 建立故障矩阵、打包验收和端到端回归 |

已有哈希去重、任务修订号、原子文件保存、SRT解析、图像排版、媒体处理、评分校验和测试值得复用；通过接口逐步拆分，不把已有验证一次推翻。

## 3. 用户操作与信息结构
主导航采用“项目 / 素材收集 / 任务队列 / 设置”。首页列出真实项目缩略图、题目、更新时间、下一步及缺口，不展示虚构的播放收益或评分。

推荐主界面为“一屏工作台”：左侧素材与步骤，中间当前编辑内容，右侧竖屏预览，下方简化时间轴。另提供同一套能力的“分步向导”，供初次使用者依次处理素材、文稿与配音、评论、导出；两种入口共享同一项目模型，不维护两套业务逻辑。

### 制作路径
1. 新建项目：粘贴X原帖链接、拖入视频，或选择已收集素材；获取元数据、保存出处和采集时间。
2. 选段：播放器拖动开始/结束点，必要时输入精确时码；原片与成片时间轴明确区分。
3. 文稿：已核实事实、口播和观察分别可读；AI建议为待采纳内容，不能把“缺证据”项自动转成事实。
4. 配音：保留“导入甜美解说音频”选项；接口配音按段试听、调语速与表达、只重做改动段落；修改文本后提醒旧音频已过期。
5. 评论：从收集箱选真实截图、裁剪副本、填链接及忠实译文；原图只读。译文/备注单独标识，不模拟网友账号和点赞。
6. 预览：中文标题、字幕、截图出现时段、原声与旁白切换可见；预览先使用代理素材，正式导出用原片。
7. 导出：显示生成计划、缺口、输出目录、已有缓存和付费服务用量。普通本地导出不重复询问授权；付费步骤在用户已选定的限额/批次授权范围内运行。
8. 导出完成：打开视频、打开素材包、查看审核记录。导出成功和内容审核通过分开呈现。

### 截图与录屏收集箱
支持用户选定ShareX保存目录，归档规范命名的PNG/视频；截图文件稳定写入后才登记，忽略临时/下载中后缀。相同哈希不重复导入。监控只负责本地收集，不自动触发付费OCR/翻译或生成。
原始目录保留用户的可读文件名；应用内部用UUID和哈希管理。项目里显示“评论1 / 原帖截图 / 标题截图”等用途，来源链接单独填写；不能根据截图文件名猜测原帖日期、作者或授权。
不接管ShareX全局快捷键和配置；先通过现有软件保存，再接入指定目录。目录监控为后续正式应用功能，本轮尚未实现。

### 内容状态与运行状态分开
内容采用现有idea→researching→drafting→review→ready等编辑状态。技术任务采用QUEUED、RUNNING、NEEDS_INPUT、SUCCEEDED、FAILED、INTERRUPTED、CANCELLED。
“视频已导出”只证明技术步骤成功。用户仍能看到事实核查缺口、估时字幕、未取得评论截图等具体信息；不要用一排统一绿色勾号掩盖这些差异。

## 4. 技术方案
推荐Windows本地桌面路线：PySide6/Qt界面，复用Python内容与媒体核心，FFmpeg执行渲染，SQLite记录运行队列。Qt官方提供桌面部署方案；初次发布先验证PyInstaller的onedir模式，便于排查依赖与媒体文件问题。正式分发再包成用户级安装程序。

| 层 | 职责 | 不应承担的职责 |
|---|---|---|
| 桌面界面 | 项目列表、编辑、播放器、进度和错误提示 | 执行耗时编解码、直接调用收费API |
| 应用服务 | 项目版本、验证、费用授权范围、任务安排与事件 | 把模型输出当成已核实事实 |
| 内容/媒体核心 | 镜头与字幕计算、评分算术、缓存、素材处理 | 依赖GUI对象或Tk状态 |
| worker进程 | 单步下载/配音/渲染，进度与结果回报 | 修改用户正在编辑的项目版本 |
| 适配器 | X获取、TTS、写稿、转录等供应商接口 | 承诺不同账号或平台统一可用 |
| 本地存储 | 项目文件、运行队列、日志、缓存和备份 | 保存明文API Key/Cookie到仓库 |

FFmpeg使用固定参数模板和参数数组；文本/URL/文件名均作为数据传递。程序升级后的渲染器、字体和模型版本进入缓存键，避免旧缓存被误当成新版本输出。
默认一个编码任务同时运行、固定保守线程数；下载/读取元数据可少量并发。以后通过实测CPU/内存和用户设置提高，不默认占满电脑，以便另一Claude项目继续运行。

### 数据位置与权威来源
- 安装目录：应用二进制和打包依赖，不写任务和用户素材。
- 用户应用数据目录：配置、诊断日志、凭证引用；实际路径通过系统API获取，不硬编码用户名。
- 用户选择的工作区：每个项目的project.json、assets、versions、exports、snapshots。
- project.json：内容与编辑状态的权威源，带schema_version、project_id、revision；可读、可导出，方便Codex/Claude接续。
- workspace.sqlite：队列、执行尝试、用量回执及项目索引的权威源；索引可由项目文件重建，不能借重建丢失费用回执。采用单写入服务与事务，迁移前备份。
- state/score-ledger.json仍是本账号正式文明账本的唯一累计源。应用项目只存评分建议；编辑账本仍走现有锁和发布依据。
- API Key：Windows凭证存储，支持仅会话使用与移除；排查包、日志和项目导出均做敏感字段过滤。

原始素材采用哈希或项目资产ID，显示名称不作为文件身份。导出可读名称例如 `20261018_题目_v003_1080p.mp4`；冲突加版本号，不覆盖已审版本。保存目录和命名规则由设置页管理。

## 5. 可靠性机制
### 自动保存与版本
编辑停止约500毫秒后保存草稿，且只标为“已保存”在实际成功之后。运行任务固定使用某个revision；界面继续编辑时产生新revision，不修改worker正在处理的输入。
重要节点创建快照：采纳AI稿、生成配音、进入审核、导出和升级迁移。恢复项目时先展示可用快照，不覆盖最后一份文件。损坏配置可重建默认值，损坏项目进入恢复向导。

### 任务队列与中断
任务作为有依赖的步骤：素材→文稿→配音→字幕→渲染。每个步骤包含输入哈希、适配器版本、尝试ID、状态、进度和输出回执。
执行前记录RUNNING，再启动worker；成功输出先写.part文件并验证，原子更名后提交成功回执。重新启动时核对输出和回执，可复用已成功步骤；FFmpeg中途退出从该渲染步骤重新执行，不宣称恢复到某个编码帧。
worker心跳和进程启动标识用于确认运行状态。恢复仅处理本应用创建且确认已无worker的运行记录，不按文件年龄抢锁，不清除.coordination/workspace.lock.json。
取消只停止本应用启动的worker/FFmpeg，保留已完成产物。关闭窗口时允许保存退出或完成当前任务后退出；后台模式作为显式设置，默认不静默长期采集。

### 收费调用的结果未知
收费请求先记录请求ID、输入摘要和授权范围；成功后保存服务回执、用量和音频缓存。超时或“服务已成功、客户端还没保存就崩溃”进入NEEDS_INPUT/结果待核对，而不是自动重试。供应商有幂等键或查询接口时再利用它们；无法证明幂等时，不承诺绝不重复扣费。
费用显示实测值、估算值或不可得，不把未知填0。估价使用标注日期和服务的价目表；设置日/批次字符数、请求数和费用上限，额度不足时暂停相关步骤。本地导出继续可用。

### 失败信息
每条错误给“发生在哪一步、已保留什么、可执行的下一步”。例如下载失败可以导入本地文件，磁盘不足给目录与所需空间，字幕越界定位具体行。技术堆栈默认收起，可导出已脱敏的诊断包。
目录检查在任务开始前执行；开始写入前估算空间并考虑中途磁盘满，失败不得把不完整文件标为成功。更新替换程序时保留工作区；工作区备份独立于安装包。

## 6. 输出与剪映关系
首个正式版交付带字幕MP4、无字幕MP4、SRT、原始素材引用/复制包、分段配音、镜头清单与来源审核信息。用户可以继续在剪映中精修。
普通MP4不会还原剪映多轨。自动写入剪映草稿需另做版本兼容层和真实客户端验收，不作为安装包或正式版的隐含承诺。
应用内视频预览须验证QtMultimedia和实际MP4/AAC文件兼容；失败有缩略帧/代理播放和外部播放器入口。输出可由FFprobe/PyAV复核，播放成功不能单独证明内容正确。

## 10. v0.2内部测试版实际实现
用户已授权实施一屏工作台。新版代码在studio/与studio_entry.py，复用pipeline/core.py；旧Tk工具及.pipeline任务原样保留。当前提供本机内部构建，尚未做干净Windows、全面断电/升级回滚或对外分发验收。

### 启动与操作
- 本仓库入口：双击根目录`地球人日志工作室.lnk`，使用`.studio`工作区，已复制迁移用户提供的8秒技术样片。
- 独立程序（当前0.3.1）：`dist/0.3.1/EarthPeopleLogStudio/EarthPeopleLogStudio.exe`，整个文件夹需保持完整；安装入口`dist/EarthPeopleLogStudio-0.3.1-Setup.exe`。安装器不要求管理员权限；应用自带运行时，日常不需要CMD/Python/Codex。
- 直接启动EXE默认使用用户Documents下“地球人日志工作区”，配置位于LocalAppData/EarthPeopleLogStudio；也可通过界面选择工作区，重启启用。命令行`--workspace`是开发/便携入口，不写用户全局配置。
- 左侧新建/切换项目或复制导入旧job.json目录；中间编辑素材与选段、文稿与声音、真实评论、文明观察与审核；右侧播放原片或队列中的成片。
- 拖动预览进度条，点“当前画面设为起点/终点”，或输入精确秒数。原片与成片预览有明确标签；未渲染的文字/截图不在原片预览中实时合成。
- 默认保留甜美解说音频导入。当前新版不提供收费API按钮；复制写稿提示词可交给现有AI。没有配音不会自动合成声音，估时字幕仍须试听校准。
- “生成视频草稿”固定输入快照，单个独立worker执行；期间可继续编辑或准备其他项目。同一输入重复点击去重，成功且哈希完整的成片复用；取消/重试在任务队列操作。
- 导出包存于项目exports下“日期_标题_r版本_任务编号”，包含preview.mp4、clean.mp4、SRT、文稿、可用配音副本、审核记录和来源/镜头引用。可在队列打开目录；MP4不是剪映多轨工程。
- 约500ms停止编辑后保存，成功才显示“已保存”。恢复入口选择项目snapshots里的JSON，恢复前文件另行备份。

### 持久契约与可靠性
工作区`projects/<UUID>/project.json`为内容权威源，schema_version=2、revision递增，job字段兼容旧媒体核心；assets哈希归档，snapshots存历史。workspace.sqlite记录任务；runs/<UUID>保存固定job.json、request.json、progress.json、result.json。worker不改正在编辑的project.json或数据库，由主界面读取回执并更新队列。

工作区使用操作系统字节锁，双开不会覆盖；worker持独立OS租约。重启仅在确认worker租约已释放且无完成回执时标记INTERRUPTED；不会按年龄偷锁，也不碰仓库.coordination。重新执行从渲染步骤开始，不恢复编码帧。已完整渲染的输出先复制到本任务.part目录并校验，再原子更名；未完成包不标成功。

FFmpeg进度按输出时间显示。取消标记只由本worker读取；Windows Job Object约束其FFmpeg子进程，worker异常退出时一起结束，不按进程名杀程序。网络下载取消可能等到当前请求超时。关闭窗口遇到运行任务会提示取消，完成后再次关闭；排队项下次继续。

工作区移动后重写所属运行快照中的内部绝对路径，并保留迁移记录；原位置仍有活跃应用/worker时拒绝接管。已导出的来源引用是当时快照，移动工作区后其旧绝对路径可能不再直接可点，素材仍在项目assets；重新导出得到新引用。项目与运行数据不要在程序运行时手工同步到另一台电脑。

当前不包含：ShareX文件夹监控、自动热榜/评论采集、自动事实核查、转录/逐字对齐、逐段语调调节、收费预算账本、后台定时采集、自动发布、剪映可编辑多轨导出、在线更新与代码签名。它们仍为后续设计；旧版MiniMax适配器没有被新UI隐式调用。

依赖固定入口requirements-studio.txt；构建时项目.runtime/wheels保留真实wheel与哈希，构建清单列出实际版本。`scripts/build-studio.py`产生onedir EXE和licenses；`scripts/build-installer.py`使用校验过的项目级NSIS3.11编译安装器。NSIS下载源与SHA256见交接；未安装系统级构建工具。

已通过25项离线检查，含保存失败不覆盖、修订冲突、JSON损坏与快照恢复、双开锁、任务快照/去重、OS租约恢复、工作区移动。真实源代码与冻结EXE分别验证视频导出、缓存复用/损坏重建、取消及worker崩溃恢复；Windows进程句柄检查确认FFmpeg随worker退出，另一个控制进程继续存活。Qt真实界面验证自动保存、关闭重开、导出中继续编辑、QProcess队列提交和MP4/AAC播放，查看了实际成片预览截图。

## 11. 0.2.1短素材快速切片
依据用户已确认的“短新闻／产品演示：已有看点，快速加工”实施。复用现有工作区schema2和运行队列，旧项目按原版式打开；新建快速项目不会清空旧稿或改写原素材。当前二进制位于dist/0.3.1/EarthPeopleLogStudio；安装包名为EarthPeopleLogStudio-0.3.1-Setup.exe，项目内快捷方式指向此版本。旧0.2程序与重复测试产物已于2026-10-19清理，历史验收记录见[清理交接](../handoffs/2026-10-19-cleanup.md)。

### 最短操作
1. 左侧“＋快速切片”，点“导入原片”。填写来源链接、来源名称及事件日期；未知日期可留空待核查。
2. 拖动右侧原片进度条，用“当前画面设为起点/终点”选范围，或输入“原片起点＋片段时长”。
3. 填写顶部标题、一句背景和一句观察。背景与观察分别呈现，默认原声、无额外配音、无评论截图、文明待评；不需要重新处理原片已有的字幕。
4. 点“导出当前片段”或右上“生成视频草稿”，在任务队列查看完成状态、播放成片或打开输出目录。

可选操作：封面原片时刻默认片段起点；可用“当前原片画面作封面”指定原片时刻。选择深色/浅色模板、1080p/540p尺寸，点“记住模板和输出尺寸”供下一次新快速项目复用。预设仅记外观与尺寸，不复制新闻文字、素材使用状态或评分。

### 同一原片多个切点
每个完整看点分别设置标题、起止点、背景和观察，点“把当前设置加入列表”。列表可双击修改各字段，时间均以原片为基准；最多20条，不等于推荐一次量产20条。空封面时刻表示该片段起点。

点“批量导出列表”前先校验所有行；存在错误起止点、越界封面或超长文字时，不提交该批。已通过的切片各自固定快照并顺序进入队列，重复的相同输入去重，当前项目后续编辑不改运行快照。磁盘故障等运行期错误仍按每个任务分别保留和报告，不承诺整个批次具备数据库原子事务。

批量切片的评估范围不同，评分/审核状态重新设为待评/未审核，不把同一个评分自动复制到多个看点。每条的标题会在队列中显示。没有自动识别“精彩”或检查语义完整性，用户仍需看片确认。快速模式保留输入视频音轨；无音轨素材不会凭空产生现场声。

### 实际输出与限制
快速输出包额外包含：cover.png封面、title.txt标题、description.txt简介、publish-copy.json发布草稿；与视频/SRT一同做哈希校验，损坏会失效重做。sources-and-shots.json来源记录包含所选原片起点、时长、背景、观察和封面时刻；并非发布回执。原片只复制到资产目录，不删除水印、翻转或修改原文件。

版式为竖屏9:16完整留边，原视频按比例放入较大主体区域，标题与背景在上方，观察与文明状态在下方；没有主体追踪裁切、横屏专用版式或实时文字叠加预览。原片预览仍只预览原片，完成任务后才预览合成稿。标题最多40字，背景64字，观察52字；复杂旁白、评论截图继续使用“新建一期”的完整版。

无自动转录、自动翻译、生成配音、背景音乐输入、热点/评论采集或平台发布。批量仅支持原声与原片已烧录字幕，不跨不同切点套用同一旁白或SRT时轴；需要旁白/独立字幕请在完整版单条制作。所有输出为内部草稿，来源与内容审核仍需人工完成，不因技术通过自动成为原创、授权或可获收益作品。

本轮源码GUI完成两条实际切片、封面/文案、原声、无效行拦截、列表自动保存/重开与预设复用检查；29项离线检查通过，旧项目渲染/取消/恢复/内嵌播放回归通过。冻结程序与安装包的最终结果见handoffs/2026-10-19-quick-mode.md；未做干净Windows或真实平台发布验证。
