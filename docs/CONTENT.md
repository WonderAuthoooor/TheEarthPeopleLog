# 内容主体设计与写作规范
版本：v0.2｜2026-10-11｜性质：项目原创编辑方案；运营参数待试验。短视频以第12节的新制作结构为准。

## 1. 核心承诺
每篇让读者带走三样东西：发生了什么、为什么与我有关、这件事暴露了人类什么特点。
账号标语候选：记录地球人的进展、故障与偶尔的灵光。
内容的最小单位是“一个可核对的事件 + 一个清楚的解释 + 一个有记忆点的观察”，不是新闻摘要堆叠。

## 2. 观察者人设
地球常驻档案员：有距离感，但与人类同在现场。用“我们”多于“你们人类”。
理解普通人的处境，追问有权力者和规则制定者的责任。对证据认真，对自以为是保持幽默。
可采用明确虚构的外星观察员卡通形象（2026-10-20用户选择可爱卡通包装）；正文不伪造现场身份、专业资格、内幕渠道或采访经历。
价值判断可以明确，事实不能由阵营、品牌喜好或广告客户决定。

## 3. 内容范围
优先：科技能力与实际用途；产品承诺与消费者体验；公共规则与日常协作；可靠的科学进步。
选择性覆盖：与上述主题有联系的国际人物言论和社会争议。
低优先：纯明星私生活、无新增信息的骂战、只有惊吓或伤亡细节的流量素材。
公共价值重大但“不好笑”的事件可以严肃呈现；不能为了统一人设硬加包袱。

## 4. 三个栏目
| 栏目 | 读者问题 | 结构 | 初始比例 |
|---|---|---|---|
| 今日地球记录 | 今天这件事到底怎么回事？ | 关键事实—影响—观察—记账 | 60% |
| 地球人使用说明 | 这种事为什么总会发生？ | 事件入口—机制解释—现实意义 | 30% |
| 文明周报 | 上周热闹完了，后来呢？ | 新进展—旧判断修订—账本回顾 | 10% |

比例用于规划选题，不是固定配额；周报对旧事件不重复记分。
积极进展与问题都应被主动搜寻，不设强制正负配比，也不让“负面更容易火”决定全部样本。

## 5. 选题评分
热度与新进展20、受众关联25、反差与可解释性20、证据完整25、后续价值10，总计100。
70分作为初始优先线，不构成流量预测。核心事实不可核查时，只能保留线索或写清“谁提出何种说法”。
每张选题卡写：一句事实、一句读者收益、一句独特观察、至少一种可能推翻当前判断的证据。
热点已过但有新增证据/结局/更好的解释仍可做；不能旧闻冒充刚发生。

## 6. 叙事节奏
- 开头：直接给最值得注意的事实或矛盾，让人知道继续看能理解什么。
- 事实：交代主体、动作、时间、范围和来源。首先解决“发生了什么”。
- 解释：只围绕一个主问题，不一口气讲完整产业史。
- 观察：把事实背后的行为或机制讲清，再给笑点。
- 结尾：一句文明评分依据与一句余味；没有足够证据就待评。

起始长度参考：短视频60—120秒；图文5—8张；文章800—1500中文字符。按信息量和真实反馈调整。
短内容一篇一个主判断；复杂争议宁可拆分，拆分稿仍须保留必要限制。
不把来源、反例和不确定性都藏到读者看不到的位置。

## 7. 幽默写作方法
笑点应让解释更清楚。优先选择：
1. 期待与现实的反差：承诺很宏大，真正的改善很具体。
2. 尺度错位：把航天级愿景与生活中的小阻力并置。
3. 冷面档案腔：用平静记录呈现荒诞，不靠感叹号要求读者发笑。
4. 日常类比：把复杂概念换成容易理解的场景，并说明类比边界。
5. 回扣：结尾回应开头的关键词，让读者自然记住主题。

操作顺序：先写准确的无笑点版本 → 找真实矛盾 → 写三个笑点候选 → 删除新增事实或暗示动机的候选 → 保留最短、最有解释力的一句。
60—120秒稿通常尝试一至两个笑点；这只是起稿约束，不是配额。
灾难伤亡、个人创伤、弱势者遭遇默认不用笑点；可在独立评论中讨论失责，但不能娱乐化受害者。

## 8. 自创示例（均为虚构训练场景，不能当新闻发表）
场景A：某工具仅更改名字，功能无已证实变化。
- 平铺：工具更名，但功能没有变化。
- 观察：本次升级发生在名片上，能力栏仍待更新。
- 不用：骗子又来割韭菜了。（凭空认定动机与欺诈）

场景B：某办事流程实现一次填表、多处复用。
- 观察：地球人终于让数据多跑了几步，少让申请人练几趟折返跑。
- 不用：一个改革彻底解决所有办事难题。（范围失真）

场景C：某公共系统发生故障，原因未明。
- 可写：目前确认的是服务中断，尚未确认的是故障原因。
- 不用：服务器也被这届人类气下班了。（若掩盖重要事实、影响受害者则删掉）

场景D：假设某产品的安全缺陷已被可靠确认。
- 评论候选：功能清单可以很长，安全这一项不能写成选配。
- 限制：不能把此句提前套用到尚未核实的真实品牌。

## 9. 标题和封面
每稿写三个候选：事实型、矛盾型、问题型；必须都能由正文支持。
- 事实型：某项规则改了，实际改变的是这两件事。
- 矛盾型：名字升级之后，能力升级了吗？
- 问题型：测试中出现故障，哪些结论现在还不能下？
这些只是句型，真实标题必须替换明确主体和事实。
不使用无证据的“全网封杀”“实锤造假”“所有车主”“必然崩溃”。
问号不是免责符；不能把没有依据的指控改成问句。
封面不补造现场、不偷换车型/人物、不把示意图当实拍。
开头及时兑现标题承诺，不故意把唯一答案拖到最后。

## 10. 平台适配
先写事实母稿，再做版本；不逐平台重新发明事实。
- 短视频：口语化、一个主问题、必要画面证据、字幕标出处与时间。
- 卡片图文：每张一个信息，事实/观察/评分有清楚区分，末页保留来源和更新入口。
- 长文：补背景、证据分歧、完整评分和后续。
- 周报：连接旧稿、解释变化；不能只拼接旧文冒充新分析。
平台能力与规格发布前查官方帮助或实际后台，不宣称某种长度受算法必然偏爱。

## 11. 风格与成稿验收
| 项目 | 通过标准 |
|---|---|
| 事实 | 每个核心主张可定位来源，标题不扩大范围 |
| 价值 | 读者能用一句话复述获得的新理解 |
| 观察 | 有依据，不是替当事人编造动机 |
| 幽默 | 自然、简短、无事实污染；严肃事件允许完全没有 |
| 评分 | 与热度独立，可解释，可追溯 |
| 阅读 | 开头有信息，段落单一功能，无术语堆砌 |
| 商业 | 披露相关利益，不把评分变成广告 |

内部可按信息价值、叙事、解释、表达各0—5分复盘；事实/素材/授权硬门槛不允许用其他高分抵消。
删除套话：引发广泛热议、值得我们深思、让我们拭目以待（除非具体说明谁讨论、思考什么、等待什么）。

## 12. 动态新闻评论视频（用户反馈后重做）
用户认为首版七张静态信息卡配音无趣。技术上可导出、字幕同步，不代表内容质量合格；preview-v1保留为流程样片，不作为发布成品。

默认结构：事件原片交代背景 → 原创幽默解释配相关画面 → 真实网友评论与观察员回应 → 文明指数结算。每部分服务一个具体问题，不机械填满模板。

| 部分 | 建议时长（非平台规则） | 观众获得什么 | 制作要求 |
|---|---|---|---|
| 事件入口 | 0–8秒 | 谁做了什么，矛盾在哪 | 先给有信息量的事件画面或原声；当屏写日期和必要背景，不放长片头 |
| 背景与解释 | 8–35秒 | 事情实际改变了什么 | 原片、文件关键句、相关实拍/原创演示随口播切换，完整保留范围限制 |
| 评论与原创回应 | 35–55秒 | 别人怎么看，我们补充什么 | 通常1–2条真实评论，每条都要接原创解释或包袱，不连续朗读评论墙 |
| 文明结算 | 最后5–8秒 | 为什么加减这个分 | 动态账本只突出分数与一句依据；幽默可回扣开头，评分不可由情绪决定 |

总长先试55–75秒，按实际配音与素材调整。以上秒数为分镜预算，不是已测成片时码。
每个镜头写清作用：证明事实、解释概念、铺垫/兑现笑点、呈现回应、结算。无作用的画面删掉；不能用游戏、豪车、影视搞笑片段无关铺底。
通常在2–5秒内有一次信息或视觉变化；原话、文件和评论须留足阅读时间，不为频率硬切。运动可以是原视频动作、文件重点跟随或演示操作，不等于给静态卡片反复加缩放。
新闻原声短暂保留现场感，旁白进入时降低背景声；笑点前留自然停顿，少量音效辅助动作，不持续塞罐头笑声。

### 画面与幽默
- 先写一句准确解释，再把它变成能看见的动作。例如“更名不证明能力”：演示文件夹改名，硬盘容量未变；标明原创类比演示，不冒充产品测试。
- 一个主包袱配一个结尾回扣即可，不把每句话都改成嘲讽。讽刺主张与行为，不靠外貌、疾病、群体标签取乐。
- 画面证据与类比镜头分明，其他日期现场标注资料画面；不把其他行政令的签署镜头说成此次改名令的签署现场。
- 来源小字随相关镜头出现；主体字幕简短，不让观众同时读长文、评论和旁白三套文本。

### 网友评论
- 保存原帖链接、评论定位、获取日期、原文与上下文。真实截图可裁剪放大，遮挡无关账号信息，保留出处；外语另附忠实翻译。
- 不伪造点赞数、用户名、评论截图，不把原创段子署成网友发言。没有合适评论时，直接改为“观察员备注”。
- 选一条有解释价值或反差的评论优于挑一排辱骂。不宣称少数精选评论代表全网或多数人。
- 若文字可读但截图未取得，记录“已核对文字、原截图待取”，不能声称素材到齐。

### 制作顺序和验收
先核对事件并找可用画面 → 做开头8–12秒和完整分镜 → 定口播及笑点 → 取得素材 → 再进剪映配音、剪辑。AI负责找来源与精确素材清单，用户只处理登录或更省事的少量操作。
视频过稿分两层：技术（声音/字幕/导出）与内容（开头信息、画面理由、笑点、独特观察）。第一条不能只因技术通过就推进发布。
收益假设：开头背景提升理解，中段解释争取观看，评论回应鼓励有内容的互动，固定结算帮助记忆账号。效果须用实际留存、完播、分享和关注检验，不保证爆款；评论量不单独代表内容成功。

## 13. 轻量切片试运行（2026-10-14当前优先）
用户要求现阶段提高产量，做新闻切片赚钱。沿用动态画面、事实与观察分离的方向，简化第12节制作成本，不默认完成每条复杂动画与评论截图。
- 初期选题建议仍集中科技产品演示、公开发布活动中的一个具体变化；需查明原素材与使用依据，不因科技标签推定免于新闻/平台要求。
- 初始结构25–45秒：前2–3秒直接呈现关键变化；随后约8–15秒保留有上下文的事件片段；再用10–20秒原创解释一个问题；最后3–5秒文明结算。按实际信息量调整。
- 网友评论为可选，有真实且有价值的评论才放；省去长片头、复杂动效和无关反应素材。片段长度只是剪辑预算，不是版权免责阈值。
- 每条交付最小包：原链接和日期、已核对原片时码、素材取得/使用状态、100字左右口播初稿、一个标题、一个封面句、评分理由和来源。未看视频不能伪造精确切点。
- 保留自己的解释或观察，不能把裁切、镜像、变速、去水印、换字幕当作新增内容或原创证明。
- 同一事件拆条只有在各条有独立问题且上下文完整时采用，不为了数量重复包装同一结论。
- 评分规则不变，信息不足显示待评，不因赶进度记0；模板化生产不能覆盖核查。
执行先做3条的小批次，测真实工时和观感，再按PROJECT建议尝试7天节奏。当前未选定新事件，不把10月11日的旧题当10月14日突发。

### X视频与评论选材（2026-10-14用户补充）
用户希望先从X找有热度的视频，下载后配有趣的评论截图，剪辑到抖音等平台。X作为当前优先素材线索入口，不因跨平台就推定原创或许可。先挑一条，核实原发主体、日期与上下文；评论保留真实原文和忠实翻译，再加入账号自己的回应。建议先试一个片段加1–2条评论，总长30–45秒；这属于编辑试案。下载、已看原片、核实热度、素材使用依据各自记录，不能互相替代。公开搜索无法确认原帖或评论时，明确缺口，由用户提供帖子链接或实际素材；不虚构实时热门榜与切点。
