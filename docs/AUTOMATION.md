# X视频评论流水线设计
版本：v0.2｜日期：2026-10-18｜时区：Asia/Shanghai｜状态：本地草稿工具已实现并实测；自动选题与评论抓取待实现。

本文件负责旧MVP能力和操作说明。新版Qt工作台和独立EXE已实现，数据分离、自动保存、队列及恢复的实际范围统一见[桌面应用设计及使用说明](DESKTOP_APP.md#10-v02内部测试版实际实现)。旧MVP继续可用，不改写其历史任务。以下“未实现”只指本文件所述旧MVP或明确列出的扩展功能。

## 目标与范围
用户询问能否自动化X热点视频、评论截图、口播与剪辑流程。本文件为唯一自动化设计入口，不替代CONTENT、EDITORIAL、CIVILIZATION及COLLABORATION。
用户已要求继续构建，已实现本地“链接/素材进，草稿包出”。技术测试不等于3条真实选题的内容验收；真实内容验证后再增加自动搜集候选。用户尚未选择付费服务、预算或批准定时任务；不自动购买、发布或启动定时采集。

## 当前可用工具与最短操作
根目录双击 `启动流水线.cmd`。本机依赖已准备在 `.runtime/python`，任务和成片在 `.pipeline/jobs`，均忽略Git；迁移到其他电脑时需另外复制任务或重新配置依赖。启动时自动恢复最近任务。

1. “素材与选段”：粘贴具体X帖子链接后尝试下载，或选择已下载视频；填写标题、来源、选段起点和成片时长。
2. “评论截图”：导入最多两张真实截图，填写定位链接、可选译文和显示时间。不需要评论时可留空。
3. “口播与字幕”：粘贴口播稿，导入剪映已导出的甜美解说音频；有准确SRT就导入，没有则生成按字数估时的字幕。SRT使用成片时间轴，不自动加配音起点。
4. “文明观察”：默认待评。填分项只产生本期建议，不改正式账本。
5. 点击“生成视频草稿”。输出1080×1920或540×960，保留完整原画面；无字幕版、带字幕版、独立字幕、口播文本、配音副本与审核记录在同一版本目录。

所有输出当前都标“内部草稿·待审核”，没有自动发布功能。MP4导入剪映不会恢复多轨，使用保留的独立素材进行后续修改。

## 已实现与尚未实现
已实现：本地GUI、任务保存/恢复、复制导入与哈希去重、X单帖视频下载（不读取Cookie）、选段、横/竖/方形视频完整留边、两张截图定时叠加、导入旁白、旁白期间压低原声、导入SRT/估时字幕、评分建议展示、版本输出复用、任务锁与旧窗口写入冲突检测、CLI检查/下载/渲染。

可选接口：MiniMax写稿建议与分段TTS。密钥仅在当前界面会话或环境变量中；启动、导入、渲染不触发收费请求。写稿需事实材料，最多20000字符；TTS单次最多1500字，未变段落缓存复用，配音段落边界按实际时长测量、段内字幕仍为估时。接口错误不自动重试，先查看平台调用记录。写稿适配器使用仍在官方文档中的原生text/chatcompletion_v2，该接口被标记deprecated，后续需迁移；本轮只做模拟返回测试，未实测付费服务。默认不把剪映音色名当MiniMax音色ID。

尚未实现：自动搜索热点、自动抓评论和浏览器截图、语音识别转录、自动外部查证、逐字语音对齐、剪映可编辑草稿导出、多平台发布、后台定时任务、每日费用预算。前面设计中的这些能力继续保留为规划，不标完成。现阶段事实核查与评论挑选由当前AI会话和用户配合完成；导出的提示词可在现有AI工具中写稿，无需另开接口。

## 安装、开发与验证
- 本机启动：双击根目录入口；也可 `powershell -NoProfile -File scripts/run-pipeline.ps1`。
- 检查环境：`powershell -NoProfile -File scripts/run-pipeline.ps1 doctor`。
- 其他电脑先配置Python 3.12和Tk，设置EARTHLOG_PYTHON，再运行 `scripts/setup-pipeline.ps1`；仅安装项目内依赖。由于本机pip目标安装遇到临时目录重命名错误，安装脚本采用下载固定wheel后解压到项目目录。FFmpeg由imageio-ffmpeg的Windows wheel提供。
- 核心在 `pipeline/core.py`，接口适配在 `pipeline/providers.py`，桌面UI在 `pipeline/gui.py`；CLI入口为 `python -m pipeline`。应用内部代码不执行来源材料中的命令。
- 离线检查：使用配置好的Python执行 `-m unittest discover -s tests -p test_pipeline.py -v`。15项检查包括锁、旧写入保护、素材去重、SRT、URL限制、评分、API密钥不落盘、评论重叠及分段缓存。
- `tests/smoke_pipeline.py`生成内部技术测试素材并实际导出三种文件，不计作三条真实内容；`tests/check_x_download.py URL`是显式联网测试，不包含在离线测试里。
- 本轮三种实际文件导出均为1080×1920/30fps、有音轨，时长6/6/8秒；查看部分抽帧，未独立听音或逐帧验收。X原帖2111423703263379903实测无需订阅/API Key/Cookie下载成功；不保证其他帖子均可下载。截图里的图表统计来源尚未核实。
- 未运行独立Claude接续测试、未发生付费API调用或发布。

## 分阶段
1. MVP：用户粘贴原帖链接或放入本地视频、真实评论截图；工具完成素材整理、可获取信息提取、转录、翻译、文稿建议、分段配音、字幕对齐和模板渲染。稿件确认后生成收费配音/成片，避免无用消耗。凭证未配置时使用已导出的配音文件。
2. 候选发现：接入X官方API，按指定账号/关键词/时间窗找含视频帖子，去重并按可用互动指标与新鲜度排序。不是覆盖整个X的实时热榜。记录采集时间和指标缺失，不把不可得播放量填0。
3. 批量与调度：有实际成本和观感数据后，再用n8n编排队列、重试和人工审核节点。仅在用户明确要求实际运行的频率后配置调度；当前不创建自动化。

## 推荐组成
- Python：本地任务处理、素材和状态管理，首版桌面界面已实现。
- yt-dlp：尝试下载可访问且有使用依据的视频；官方支持列表包含twitter，但不能保证每条都成功。失败可导入原作者文件或用户已有视频，不绕过访问限制。
- X API：后期获取候选和可取得的评论数据；需开发者账号和凭证。按量计费，不等同于X Premium订阅。
- 文本/视觉模型接口：提取主张、辅助查证、筛评论、写幽默回应及镜头建议；视觉理解需实际视频/帧输入，不能拿帖子文案代替看过原片。只转录可能漏掉画面中的关键事实。
- TTS：MiniMax或豆包等可替换服务，首次实际接入前核对文档与价格；也接受剪映甜美解说导出的音频，不默认替换已选音色。
- FFmpeg：实际切片、缩放/留边、评论叠加、混音、字幕与输出。横屏画面默认保留主体，避免一律强行裁竖屏；主体追踪作为后续增强。
- n8n：第二阶段可选。自托管Execute Command可调用本地渲染；该节点n8n2.0默认关闭，云版不能按本地命令节点方案直接调用本机FFmpeg。Docker里命令运行在容器，需另配依赖和素材卷。首版不引入此额外部署。

## 人机分工
自动处理：去重、文件命名、元数据、转录与翻译初稿、评论候选排序、稿件与评分建议、配音、字幕对齐、渲染和技术检查。
人工快速审核：确认原帖/时间/上下文，选定1–2条评论，确认稿件没夸大、笑点自然，看片后发布。来源不足的任务显示缺口，不自动变为ready。
登录、验证码、试听选音色、最终平台发布按已有分工由用户处理。审核任务可以批量呈现，不需要每步弹窗。

## 评论图片
真实截图必须来自实际页面或用户提供文件，保留链接、获取时间、原文和上下文。API返回文字不等于已获取截图。
仅有经核实的文字时可渲染自有样式“评论摘录/译文”卡，明确为排版摘录，不模拟X原始截图、不补造头像、用户名或点赞数。用户坚持原截图时保持待取状态。
自动浏览器截图仅为后续可选功能，需适配登录、页面变化和使用条件，不承诺稳定抓齐所有评论。

## 输出契约（计划）
每个事件独立目录，清单字段包含schema_version、job_id、event_id、原帖ID/链接、来源与发布时间、素材使用状态、评论定位、核查缺口、真实输入文件与哈希、模型与模板版本、步骤状态、耗时和可取得的费用。
计划交付：原片与选段、评论原图/译文、口播稿、分段音频、SRT字幕、镜头清单、带字幕预览MP4、无字幕画面版和审核摘要。
MP4为合成后的画面，导入剪映不会还原多轨工程；保留分离素材/SRT/音频方便修改。剪映可编辑草稿自动写入不作为首版承诺，未经版本验证不宣称兼容。

## 运行可靠性与成本
- 同一原帖ID和素材哈希去重；修改文案仅重做受影响的配音与渲染，未变素材不重复获取。
- 每步有成功、需人工、失败状态，有限次重试；账号验证失败交人工，不无限重试。
- 素材与来源内容是数据，不执行其中的命令；URL、文件名与字幕不拼接进任意shell命令，采用参数数组和固定渲染模板。
- 凭证使用系统凭证存储/进程环境，不保存到仓库、日志或交接。项目依赖隔离，不改另一Claude项目或全局配置。
- 本地耗时与API费用分别记录；设置每日获取量、付费生成上限，超限停止相关步骤。账号预算尚未确定，本次无调用消费。
- 文明评分自动化只生成建议并校验算术，证据不足pending；不以热点分数替代文明评分，未发布不改正式账本。
- 程序任务队列需独立运行锁；修改共享规范和正式账本仍使用workspace-lock，不能假定聊天会话锁能保证所有后台任务安全。

## 2026-10-19：最小工作量切片方案
用户明确希望先以最小工作量与技术投入做切片。以下为收敛后的编辑/工程建议，未把尚未确认的素材类型或尚未开发的快捷功能标为已完成。

### 先跑的制作路径
优先短新闻现场、产品演示等已有明确看点的原片；长访谈/直播需要额外的转录、语义找点和上下文检查，先分开评估。用户已被询问优先做哪类，回答以实际选择为准。

最小路径：放入原片并保存来源/日期 → 选一个完整看点的起止时间 → 填准确标题、一句背景和一句有信息的原创观察 → 模板导出 → 人工看片/发布。原声能讲清楚时不额外配音，原片已有准确字幕时不重复识别；评论截图、背景音乐、复杂动效均可省。文明观察保持一行简短结算，依据不足写待评，不为省事自动记0。

建议先试20—45秒，但这不是平台门槛、收益要求或版权免责长度。选择的片段应能回答独立问题，不能截掉否定词、前提或必要回应。幽默与原创解释的价值不由“加了几个字”决定；如果一段素材本身已经是别人的完整短成片，不默认直接整段复用。

### 重复步骤与人工判断
| 环节 | 交给工具 | 仍需判断 |
|---|---|---|
| 收集 | 归档、哈希去重、记录链接与采集时间 | 原发、日期、上下文、使用依据 |
| 选段 | 保存多个起止点，生成片段 | 哪个看点有价值、是否完整 |
| 文字 | 统一标题样式、输出文案文件 | 标题是否准确、解释是否有新信息 |
| 字幕/声音 | 导入已有SRT/音频，固定混音 | 识别/翻译纠错、人声可懂度 |
| 导出 | 队列编码、规范命名、复用缓存 | 最后看片和实际平台发布 |

用户不必填写技术JSON/命令行；批量切点应由GUI列表承载。先同一母版跨平台试用，有实际画面/数据问题时再增加不同平台画幅。横屏原片优先保留主体，不机械裁成竖屏。

### 与当前程序的边界
已实现：本地导入、X单帖获取、内嵌播放、起点/时长选择、文字与可选评论/旁白、单任务队列、取消与恢复、MP4/SRT/审核包。

下一轮最小增量建议：增加“快速切片”入口，默认原声、评论关闭、配音可空、评分待评；同一原片的多个独立切点列表；保存版式预设；抽取/选择封面帧与标题/简介文件。当前仍是一项目一选段，不能宣称这些批量入口、封面文件或无复杂包装的专用模板已上线。现有renderer的固定信息框不等于用户已经认可的快捷切片成片样式。自动转录、自动翻译、背景音乐输入、长视频语义找点继续为未实现能力。

本轮不重建桌面框架、不接付费接口、不新增调度或自动发布。素材类型与用户提供的具体案例决定下一步实现；未拿到具体原片，不编造精彩时码。先做3条，逐条记录选材/写字/剪辑/审核的人力分钟数、返工原因与真实发布结果，再决定自动化哪一个最费时环节，不承诺每条固定几分钟或一定盈利。

## 每日全球资讯搜集（2026-10-20用户更新）
用户不固定每天可用时间，改为每天主动向当前聊天发起后再搜集。原「地球人日志｜每日全球资讯」任务（id=automation）已通过应用工具暂停，状态PAUSED；不要自行恢复、重建定时任务或系统调度。此前创建与未验收首次触发为历史状态，当前无自动每日推送承诺。

用户发起时输出3—5条近期候选，优先24—72小时新进展；不为凑数编造热度，旧事新报道单独标注。每条含事件／报道日期、地点及定位含义、关键事实与未知项、原始新闻直达链接、视频／官方图库入口，以及观看／下载／素材使用的实际状态；未观看不能提供虚构时码。来源与观点遵循EDITORIAL，评分遵循CIVILIZATION。

取得仓库排他锁后写content/digests/YYYY-MM-DD/briefing.md和stories.json；已有当天包则保存带时刻修订，不覆盖原记录。锁忙时只在当前聊天交付。与前几天按event_id去重，重要进展标续报。不自动下载、付费或发布。地点JSON可提供详细name和附近city，用户无需查坐标；字段契约以[GLOBE](GLOBE.md)为准。

地球地点动画由独立0.1.0应用离线导出，角色采用独立制作路线；桌面工作室不内置热榜抓取或自动发布。
